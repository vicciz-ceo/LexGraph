# Sprint: Israel — definition completeness on the full corpus

## Mandate

From the program (read `design_sections` first — do not re-derive recon):
every definition in Israeli law is captured, including definitions living
outside canonical הגדרות sections, with correct scope; scoped definitions
assert only within their scope; completeness measured on the FULL
israeli-laws-wiki corpus (director decision 4), not fixtures.

Recon facts to build on (dossier §3): corpus at
`/Users/nerya/AI for others/israeli-laws-wiki` — 6,133 laws,
`data/laws/*.wiki` + `.meta.json`, 168 MB, format matches the existing
ingester. Confirmed-missed classes today: (a) `בפרק זה`/`בסימן זה`/`בחלק
זה`/`לפרק זה` scoped definitions (498/200/68/46 files); (b) 3-word
`לענין/לעניין סעיף זה` trigger variants (~589 files); (c) ad-hoc
`(בפרק זה - X)`/`(בסימן זה - X)` markers; (d) STRUCTURAL: prose-body
definition sections — heading `הגדרה` matches but body has no `:-` markers,
extraction yields [] (חוק החברות הממשלתיות art.16).

## Acceptance gates (program manager-defined)

- **I1 — The whole Israeli corpus loads.** All 6,133 laws ingest through one
  documented command with a measured report (rows, per-file failures, wall
  time, peak memory) — the same standard as the US 2,045,897-row run. The
  corpus directory is READ-ONLY; never modify the POC folder.
- **I2 — The four missed classes are captured** (a-d above), each with RED
  tests built from real corpus rows before implementation.
- **I3 — Scoped definitions assert only within their scope** on the real
  corpus, proven live-path in both directions, including סימן/פרק/חלק units
  and the סעיף-level variants.
- **I4 — Zero-miss sweep (director bar).** QA adversarially sweeps the full
  corpus for definition signals; every hit is either captured or proven
  not-a-definition. Any confirmed miss fails the gate.
- **I5 — Nothing regresses.** All 167 existing IL tests green unchanged;
  false-positive conflicts escalate per P-R2 rather than being traded away
  silently.

3. **[Phase B] I2(b) -- `לענין/לעניין סעיף זה` 3-word trigger variant.**
   Same grammar as the already-trusted 2-word `לענין זה`/`בסעיף זה`

   test_class_b_le_inyan_seif_zeh_three_word_variant_is_captured`.

4. **[Phase B] I2(c) -- ad-hoc parenthetical `(בפרק זה - X)`/`(בסימן זה -

   unchanged -- Planner's corpus scan found only 46/1041 sampled real
   instances would even exceed that cap, and zero verb-shaped (non-term)
   false positives in a targeted sweep. RED test: `...missed_classes_
   live.py::test_class_c_adhoc_parenthetical_beperek_zeh_marker_is_
   captured`. Note the dossier's originally-cited example (רכבת תחתית
   מטרו art.13) does NOT reproduce (see log) -- the fixture/test uses the
   corrected real example (חוק החברות הממשלתיות art.50א) instead.

5. **[Phase B] I2(d) -- prose-body הגדרות/הגדרה sections yield `[]`.**
   THE BIGGEST FINDING OF THIS SPRINT: 592 real corpus files (~9.7% of
   the whole corpus), not the dossier's single example -- see log for the
   full scan. At least THREE distinct body sub-shapes need handling: (i)
   single inline `TRIGGER, "term" - definition.` sentence, no list at all
   (dominant by count); (ii) `::-` (double-colon-dash) entries under a
   `TRIGGER -` preamble line (`_ENTRY_START_RE` requires exactly `:-`,
   never matches `::-`); (iii) numbered `: (N) "term" -` entries under a
   `TRIGGER -` preamble, where a naive fix MUST NOT mistake a numbered
   CONTINUATION of one definition's own text (e.g. a deduction-formula's
   sub-items, see log's "בסיס המשכורת" example) for N separate spurious
   definitions -- this is the sprint's highest false-positive risk, see
   log escalation E3 for the proposed boundary rule. RED tests (3, one per
   sub-shape): `...missed_classes_live.py::
   test_class_d_prose_body_definitions_section_yields_zero_today`,
   `...test_class_d_variant_double_colon_entry_list_under_a_trigger_
   preamble_is_captured`, `...test_class_d_minimal_single_sentence_
   variant_is_captured`.

6. **[Phase B] I3 -- scope enforcement, both directions, for `בפרק זה`.**
