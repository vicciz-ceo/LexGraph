# Sprint: Puerto Rico — Spanish-language definition rules

## Mandate

Recon finding (dossier §6, B3b): the US-PR corpus (23,636 rows) is written
in SPANISH and is 100% invisible to the English-only USProfile. ~529 real
`Definiciones` headings (`is_definitions_heading("Artículo 3. Definiciones")`
→ False, verified live); Spanish drafting idioms measured in a 4,000-row
sample: `significa` 1,006, `A los fines de` ("for purposes of") 261,
`se entenderá por` ("shall be understood as") 26. This sprint builds the
Spanish rule set for PR — headings, definition idioms, entry markers,
scope phrases (`A los fines de este Artículo/Capítulo…`), and citation
grammar as found in the real corpus — as its own profile or rule-module set
behind the core seam. Example row: `STATE_PR_LEY_249_2003_ART3`.

## Acceptance gates (program manager-defined)

- **P1 — Real PR statutes parse**: `Definiciones` sections are detected and
  their terms extracted, RED tests from real PR rows before implementation.
- **P2 — Spanish definition idioms are captured** (`significa`,
  `se entenderá por`, quoted-term appositions as found in the corpus),
  including definitions outside canonical Definiciones sections.
- **P3 — Scope stamped/enforced** for Spanish scope phrases
  (`A los fines de este Artículo…` → article scope, etc.) via the core
  seam, live-path both directions.
- **P4 — Zero-miss sweep (director bar)**: QA sweeps the full PR file for
  Spanish definition signals; every hit captured or proven
  not-a-definition. Report the before/after capture rate (before = 0).
- **P5 — Nothing regresses**: English-state behavior untouched (PR rules
  must not fire on English text); all existing tests green; P-R2 on
  precision conflicts.

## Bucket D final split (cycle 3)

Refined the manager's crude 65-anchored/19-residue split (own
regex-substring script, `scratchpad/mgr_bucketD_split.py`) rather than
inheriting it, per this cycle's brief. Method: reused `pr_profile.py`'s
OWN clause-splitting/stem-matching regexes (imported for analysis, not
duplicated) to derive the heading anchor term, added an SPANISH-article-
stripping pass and a "Definición de X" single-clause anchor extraction
(a genuinely new capability the crude split never handled), and searched
the FULL body (not an arbitrary truncation window — one real anchor,
`STATE_PR_LEY_77_1957_ART36_020`'s "Sistema de logias", sits at the very
END of its body) for the anchor term, EXCLUDING a real, previously-
uncatalogued page-break scrape-footer artifact (`"Rev. <date>
www.ogp.pr.gov Página N de M "<Law Title>" de <year> [Ley N-YYYY, según
enmendada]"`, 370 corpus-wide rows) that can inject its OWN unrelated
quoted law title anywhere mid-body and would otherwise falsely look like
"this row has a quoted term."

Before the anchor split runs, the 84-row bucket-D pool is first corrected
for: 1 row fully solved by the safe idiom-widening above (removed
entirely); 4 rows that actually contain a real quoted term and are
ordinary mechanical gaps, not prose (moved to ordinary workload, see
`### Cycle-3 corrections` above); 1 row that turned out to be a wholesale
cross-law/TITLE deferral via `conocido como` (a NEW correct-zero guard,
same shape as the already-pinned `STATE_PR_LEY_52_2019_ART3`).

**Result: 70 heading-anchored (up from the crude 65), 7 anchor-less
residue (down from 19) — the FINAL documented gap.**

Confirmed anchored examples (director's own 5, all verified to still
anchor under the refined method) plus 3 more shapes the refined method
newly recovers:
- `STATE_PR_CIVIL_ART236` (`Bienes; definición` → "Son bienes las cosas o
  derechos…") — semicolon clause.
- `STATE_PR_LEY_77_1957_ART5_020` (`Pasivos, definición` → "…los pasivos
  se definirán como…") — comma clause.
- `STATE_PR_CIVIL_ART1264` (`Evicción; definición` → "Hay evicción
  cuando…") — "Hay X cuando" copulative shape.
- `STATE_PR_LEY_1508` / `STATE_PR_CIVIL_ART1508` (`El contrato de
  seguro; definición` → "El contrato de seguro es aquel…") — leading
  Spanish article stripped.
- `STATE_PR_CIVIL_ART326` (`Poder; definición` → "Poder es la
  facultad…") — the row already referenced in `pr_profile.py`'s own
  comments as having no safe separator-based extraction; the heading
  anchor is what makes THIS row safe to capture at all.
- `STATE_PR_RENTAS_SEC2030_03` (`Definición de Caudal Relicto Bruto` →
  "…el valor del caudal relicto bruto…") — NEW: single-clause "Definición
  de X" shape (no `;`/`,`/em-dash — the term is the prepositional object
  of "de" within the SAME clause that also satisfies the stem match).
  Recovers 3 more real rows the same way: `STATE_PR_LEY_12_1966_ART7`,
  `STATE_PR_PENAL_ART35`, `STATE_PR_LEY_284_2004_ART3`.
- `STATE_PR_LEY_77_1957_ART36_020` (`Sistema de logias—Definiciones` →
  "…se considerará que está operando dentro del sistema de logias.") —
  NEW: em-dash compound heading, anchor term at the body's own END, not
  its start.
